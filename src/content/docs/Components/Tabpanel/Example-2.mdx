## Features

1. Uses the same tabs, API endpoints, and visual style as [Example 1](./Example-1/)
2. Switches active state with ARIA (`aria-selected`) instead of adding/removing active and inactive Tailwind utility classes
3. Uses Hyperscript [`take`](https://hyperscript.org/commands/take/) to move ARIA state to the clicked tab
4. Uses semantic tab roles (`tablist`, `tab`, `tabpanel`) to improve accessibility
5. Keeps programmatic tab switching with `activateTabById`
6. Preserves the existing Hyperscript content fetch and fade-in transition

This example is a direct port of the `aria-attribute` based example on the [Hyperscript Patterns](https://hyperscript.org/patterns/dom/tabs/) page, but featuring tab content fetched as hypermedia from api endpoints (not hard coded), plus Tailwind styling, light/dark modes, etc .

## Components

### TabPanel_A

`TabPanel_A` owns active tab state. It uses one `activateTab` handler that moves ARIA attributes rather than mutating utility classes.

<Tabs>
	<TabItem label='Scripts'>
	```js
const hs =
	`
	on activateTab(clickedTab)
		take @aria-selected='true' from <[role=tab]/> in me for clickedTab
		for tab in <[role=tab]/> in me
			if tab is not clickedTab
				set tab's @aria-selected to 'false'
			end -- if
		end -- for
		take @tabindex='0' from <[role=tab]/> in me for clickedTab
		for tab in <[role=tab]/> in me
			if tab is not clickedTab
				set tab's @tabindex to '-1'
			end -- if
		end -- for
		set panel to the first <[role='tabpanel']/> in me
		if panel exists
			set panel's @aria-labelledby to clickedTab's @id
		end -- if
	end -- activate tab
	`
	```
	</TabItem>
	<TabItem label='Tailwind'>
	```js
export const tw = {
	tabItem: 'z-10 tab-item not-content select-none font-semibold rounded-t-xl cursor-pointer ' +
		'hover:bg-orange-100 dark:hover:bg-purple-900 border-2 border-slate-600 ' +
		'bg-slate-300 dark:bg-gray-800 text-blue-900 dark:text-zinc-200 ' +
		'aria-selected:border-b-0 aria-selected:bg-gray-100 dark:aria-selected:bg-gray-950 ' +
		'aria-selected:text-blue-950 dark:aria-selected:text-orange-200'
}
	```
	</TabItem>
	<TabItem label='HTML'>
	```html
<div class={tw.container} script={hs}>
	<div class={tw.tabList} role='tablist'>
		<slot/>
	</div>
	<output id='tabpanel-output-a' role='tabpanel' aria-live='polite' class={tw.output + ' ' + maxHeight + ' ' + minHeight}/>
</div>
	```
	</TabItem>
</Tabs>

### TabPanelItem_A

Each `TabPanelItem_A` triggers tab activation and content loading, while the ARIA-selected state is managed by the parent.

<Tabs>
	<TabItem label='Scripts'>
	```js
const hs = `
	on ${trigger}
		send activateTab(clickedTab:me) to the closest <.tab-panel/>
		set panel to the next <[role='tabpanel']/>
		if panel exists
			set panel's @aria-busy to 'true'
			set *opacity of the next <[role='tabpanel']/> to 0
			fetch '${path}' as html then put the result into panel
			wait 50ms
			transition the next <[role='tabpanel']/>'s *opacity to 1 over 170ms
			set panel's @aria-busy to 'false'
		end -- if
`
	```
	</TabItem>
	<TabItem label='HTML'>
	```html
<button id={id} class={tw.tabItem} role='tab' aria-selected='false' tabindex='-1' type='button' script={hs}>
	{caption}
</button>
	```
	</TabItem>
</Tabs>

## Usage

You can switch tabs programmatically by sending `activateTabById` to the parent component.

```html title='Programmatic Tab Switch'
<button script="on click send activateTabById(tabId:'3') to the first <.tab-panel/>">
	Show Hyperscript tab
</button>
```

## Why this pattern

This approach follows the Hyperscript tab pattern where one parent handler centralizes tab state and uses `take` to move the selected attribute across sibling tabs.
